## A known deviation from the roadmap, flagged up front

The roadmap's Sprint 4 scope (item 4) called for "a minimal tool-using OpenAI Agent,"
and Sprint 5's own test plan (item 6, below) expected to test it. **That Agent was
never built** — there's no agent code anywhere in the Sprint 3–4 codebase, and the team
decided not to add one now, during Sprint 5, either. It's being dropped from scope
rather than retrofitted at the last minute. Sprint 5 item 6 below is written to match
what the app actually does (summarisation, relevance analysis, Literature Matrix
extraction, Paper Synthesis, Ask the Literature) rather than the Agent that isn't
there. If asked in a defense why the Agent isn't present, the honest answer is: the
team prioritized shipping evidence tracking, synthesis, and the chat feature solidly
within the remaining timeline, and didn't want to bolt on an under-tested Agent in the
final week just to tick a roadmap box.

## 1. Prepare Demo Mode — ✅ Done this session

**What it is:** a script, `scripts/seed_demo_data.py`, that creates one ready-to-present
demo account directly in the real database — a login, a project ("Generative AI in
Higher Education"), five saved papers, and every AI feature already pre-filled (an AI
Summary with evidence, three papers' Literature Matrix fields, a Paper Synthesis, and a
two-turn Ask the Literature conversation).

**Why this makes the demo "offline-safe":** every one of those AI results was
hand-written into the script, not generated by a live OpenAI call. Walking through
login → dashboard → project → paper detail → matrix → synthesis → chat needs **zero**
network calls. Nothing about the live walkthrough depends on the presentation room's
WiFi, a working OpenAI key, or Semantic Scholar/OpenAlex being reachable right when it
matters most.

Two of the five papers (Okafor, Dubois) are deliberately left with their Matrix fields
blank — exactly how a freshly-saved paper looks — so if the room's WiFi *does*
cooperate, there's still something to click "Extract with AI" on live, as a bonus, not
a dependency.

**How to use it, before presenting:**

```bash
python scripts/seed_demo_data.py
```

Safe to re-run — it wipes and recreates the demo account each time, so re-running it
right before you present always leaves a clean, known-good project. Login:

- Email: `demo@researchlens.ai`
- Password: `DemoDay2026!`

**Still worth doing before the actual presentation:** run it once on the laptop you'll
actually present from, and click through the whole walkthrough yourself at least once,
with WiFi off, to confirm nothing on the "core path" unexpectedly needs a network call.

## 4. Test authentication — ✅ Automated tests written

`tests/test_auth.py` drives the real `/register`, `/login`, and `/logout` routes
against a disposable test database (never your real `database/researchlens.db`) and
checks:

- A valid registration creates the account and logs you straight in
- A duplicate email is rejected
- A weak password (missing uppercase/lowercase/number/special character) is rejected
- A mismatched confirm-password is rejected
- Correct login credentials work; wrong ones show the same generic error either way
  (so a login attempt can't be used to check which emails have accounts)
- Every workspace page redirects to `/login` when you're not signed in
- Logging out actually clears the session

**How to run it:**

```bash
python -m unittest discover -s tests -t . -v
```

**⚠️ Not yet run against the real app in this session** — see the note at the very
bottom of this plan for why, and what to do about it.

## 5. Test academic search — ✅ Automated (logic) + 📋 manual pass needed

Two things can't be meaningfully faked offline (de-duplicating results from two live
APIs, filtering by year), and one thing genuinely needs a live API call to verify at
all (that Semantic Scholar and OpenAlex actually return relevant results). Split
accordingly:

**Automated — `tests/test_search_dedup.py`** (run with the same command as item 4
above): checks the de-duplication key (same DOI → same paper, even with different
casing or title; no DOI → falls back to a normalized title match) and the year-range
filter (excludes papers outside the range; excludes a paper with no known year once any
filter is active).

**Manual pass, needs a live connection — do this yourself, it's quick:**
- [ ] Search a common topic (e.g. "generative AI education") and confirm results come
      back from both sources (check the "Showing results from..." line)
- [ ] Apply a year range and confirm every result falls inside it
- [ ] Try sort by relevance / newest / oldest and confirm the order actually changes
- [ ] Search something with 15+ results and confirm pagination works
- [ ] Temporarily rename `.env`'s `SEMANTIC_SCHOLAR_API_KEY` to something invalid and
      confirm the app still works using OpenAlex alone, with a clear warning message
      (this is the "one source fails, not both" path — see `_search_academic_sources()`)

## 6. Test AI analysis — ✅ Automated (mechanism) + 📋 manual accuracy pass needed

*(Scoped to what's actually built: summarisation, relevance analysis, Literature
Matrix extraction, Paper Synthesis, and Ask the Literature — not the OpenAI Agent,
see the deviation note at the top.)*

**Automated — `tests/test_evidence_service.py` and `tests/test_matrix_and_synthesis.py`**
(same run command as item 4): this is the part of "AI analysis" that's actually
deterministic and safe to test without hitting a live, paid API —

- Evidence Tracking's quote-checking mechanism: a verbatim quote is marked verified,
  a fabricated one is marked unverified, curly-vs-straight-quote and
  capitalization differences don't cause a false "unverified," an out-of-range or
  duplicate citation is safely dropped, and the citation label formatter
  (`Smith (2023)` / `Smith and Lee (2023)` / `Smith et al. (2023)`) is correct
- The Literature Matrix save path: blank fields are stored as `None` rather than empty
  strings, and the "generated at" timestamp is stamped correctly
- `build_synthesis_capsule()`'s fallback order: Matrix fields first, then abstract,
  then a plain "nothing available" message — never silently empty
- Paper Synthesis's 2-paper minimum guard refuses to run on 0 or 1 papers

**Manual pass, needs a judgement call — use `Sprint5_AI_Accuracy_Checklist.md`
(item 3)** for: does a generated summary actually reflect the paper; is a relevance
rating defensible; does an Ask the Literature answer actually only use the papers it
claims to.

## A note on what "done" means above

Items 4 and 6's automated test files were written and syntax-checked this session, and
the dependency-free half of them (the Evidence Tracking logic in
`test_evidence_service.py`, which needs nothing but this app's own code) was actually
**run and passed** here, in this chat session. The rest — `test_auth.py`,
`test_search_dedup.py`, and `test_matrix_and_synthesis.py` — need this project's real
dependencies (SQLAlchemy, bcrypt, etc. from `requirements.txt`) to execute, and this
chat session's own sandbox doesn't have those installed with no way to add them. **They
haven't failed — they simply haven't been run yet.** The very first thing to do before
trusting this plan's "✅" marks on items 4–6 is:

```bash
python -m unittest discover -s tests -t . -v
```

on your own machine, where the app's real dependencies are already installed. If
anything fails there, that's real signal for item 7's table above — fix it before the
demo, not after.
